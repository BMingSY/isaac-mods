# 以撒 Mod 编写

根据用户的玩法需求制作可安装的 Mod，适用于新建项目和修改已有项目。按功能组织代码，不预设玩法类型、仓库布局或本机目录。

## 实现方式

- 确认目标版本及可用扩展，核对忏悔与忏悔+的差异；调用 REPENTOGON API 前确认扩展已安装。查阅游戏附带文档或对应版本的 [Lua API 文档](https://wofsauge.github.io/IsaacDocs/rep/)，不要猜方法名和回调返回值。
- 将需求拆成触发条件、作用对象、效果和结束条件。涉及叠加时明确数量与效果的关系；有影响玩法的歧义再询问。
- 修改原版效果时，确认回调能补充或拦截哪些逻辑。Lua 不能直接改写所有原生行为；确需替代道具或额外依赖时，说明限制及对道具身份、显示和兼容性的影响。
- 已有项目沿用其组织方式；新项目从必要文件开始，随复杂度拆分模块。

## 代码与资源

- 用 `main.lua` 注册 Mod 和回调，`metadata.xml` 保存名称、目录和版本。需要新增内容或图片、动画时，再添加 `content/` 和 `resources/`。
- 原版内容使用枚举；自定义内容按唯一名称查询 ID，避免硬编码加载顺序分配的编号。不同 Mod 的注册名和自定义内容名称避免冲突。
- 自定义道具、角色和实体的 XML 使用目标版本支持的格式，核对资源根目录、文件名大小写、动画名和纹理路径。XML 解析成功不代表游戏能够加载。
- 复用原版资源前确认文件实际存在；新增资源通过游戏日志和实际显示检查，不只判断文件是否存在。

## 回调与状态

- 根据功能选用使用道具、伤害、实体更新、房间切换或渲染等回调，并遵循其返回值协议；更新回调不一定能取消原版 AI。[回调文档](https://wofsauge.github.io/IsaacDocs/rep/enums/ModCallbacks.html)
- 属性修改放在 `MC_EVALUATE_CACHE`，基于本次重算值应用公式。原版已计算的效果不要重复添加；影响属性的状态变化后用 `AddCacheFlags` 和 `EvaluateItems` 刷新，避免每帧累乘或无条件重算。
- 射速与延迟按 `TPS = 30 / (MaxFireDelay + 1)` 换算；区分真实持有的道具和临时效果，并处理效果失去或结束后的恢复。[玩家 API](https://wofsauge.github.io/IsaacDocs/rep/EntityPlayer.html)
- 状态按玩家或所属实体分别记录，支持多人和子角色。跨帧引用先检查实体仍有效；创建、更新和清理只处理当前 Mod 拥有的实体，避免每帧销毁重建。
- 需要续玩的数据通过 Mod 存档接口序列化，区分新局与续玩；实体引用不直接写入存档，恢复后重新关联，避免重复生成。随机事件使用游戏提供的 RNG。
- 涉及输入或绘制时，区分物理输入与注入输入、世界坐标与屏幕坐标；检查重入、控制器归属和镜子房变换。

## 批量替换道具时

- 默认保留任务／路线道具，包括全家福、照片、钥匙碎片、刀柄／刀刃、铲子组件和爸爸的便条；结合 `ItemConfig.TAG_QUEST` 判断，用户另有要求时按其范围实现。[道具标签](https://wofsauge.github.io/IsaacDocs/rep/enums/ItemConfig.html)
- 按需求覆盖道具池结果和固定生成的底座，不默认改写角色初始背包、饰品或消耗品。
- 替换底座时保留价格、种子和 `OptionsPickupIndex`，避免破坏商店和多选一机制。

## 验证与交付

- 检查 Lua 语法和资源加载，再验证与功能有关的触发、结束、换房、多人和续玩行为；关注日志中的错误及实体数量、声音、属性是否异常。
- 算法和回调可独立验证，但不能据此宣称游戏内实测。测试保护已有存档，完成后移除临时诊断代码。
- 交付完整的可安装文件和简短使用说明。安装位置从实际环境查找；打包排除存档、日志和临时文件。
- 按用户要求进行本地安装或发布；要求先审阅时，展示具体结果，等明确同意后再推送。独立新版本不沿用旧项目的创意工坊 ID。
- 公开说明只保留功能、操作、必要兼容信息和链接；路径使用项目相对路径，不暴露本机目录或系统用户名。
